# Domain docs

Before exploring, read `GLOSSARY.md` at the repository root and relevant decisions in `docs/adr/`. If either is absent, proceed silently. The domain-modeling skill creates these files when terms or decisions are resolved.

## File structure

This is a single-context repository:

```text
/
├── GLOSSARY.md
└── docs/adr/
```

## Use the glossary vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests. If a needed concept is absent, reconsider whether the project uses it or note the gap for domain modeling.

## Flag ADR conflicts

When proposed work contradicts an ADR, explicitly surface the conflict.
